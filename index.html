[04] 核心功能說明 (CORE_FUNCTIONS)

本次專案涵蓋三大核心技術領域：

  • 基礎影像處理：透過 OpenCV 對圖片進行 RGB、灰階(Grayscale)、二值化(Binary) 與 256/16 降色階處理。
  • 人臉識別與辨識：結合 Haar Cascade 分類器抓取人臉區域，並利用 LBPHFaceRecognizer 進行特徵訓練，實現即時身分比對。
  • 自駕車車道線偵測：使用 GaussianBlur 降噪、Canny 邊緣偵測、設定 ROI 遮罩 過濾環境雜訊，最後透過霍夫轉換找出車道線並計算中心偏移誤差 (CTE)，進行自動循跡。

[05] 異常排除 (TROUBLE-SHOOTING)

  • 問題： OpenCV 報錯 Can't open file: ...\haarcascade_frontalface_alt.xml
    解決方式： 此為 C++ 底層 API 無法處理 Windows 中文路徑所致。將整個專案資料夾移至純英文路徑 (如 C:\CLASS\...) 即成功解決。
  • 問題： 虛擬環境內報錯 ModuleNotFoundError: No module named 'cv2'
    解決方式： 雖已啟動 .venv，但小房間內無套件。在終端機輸入 pip install opencv-python opencv-contrib-python 後成功執行。
  • 問題： 車道線偵測時，畫面外的雜物嚴重干擾霍夫轉換結果。
    解決方式： 加入 ROI (Region of Interest) 遮罩，透過 cv2.fillPoly 繪製多邊形，只保留畫面下半部的車道區域，大幅提升了 CTE 計算的穩定性。

[07] 任務日誌 (LOG_&_FEEDBACK)

心得：
本次專案循序漸進地從單機影像色彩處理，推進到人臉辨識與硬體控制的整合。 在人臉辨識階段，我們學會了建立虛擬環境、處理套件依賴，並理解了 LBPH 特徵比對的原理。 在自駕車階段，透過 ROI 遮罩過濾雜訊，讓我們深刻體會到「乾淨的資料輸入」對於電腦視覺判斷（如 CTE 計算）的關鍵性。整體而言，透過 Flask 架設網頁控制介面，讓我們對物聯網全端應用有了更完整的實作體會。

建議：
樹莓派在同時處理即時影像運算（如即時車道線繪製）與馬達控制時，有時會出現些微的畫面延遲與發熱現象。建議未來可以嘗試降低攝影機解析度，或是加入多執行緒（Threading）來分擔 CPU 的負載。 此外，在 Windows 開發環境與 Raspberry Pi 之間切換時，路徑編碼（如中文路徑報錯）需要特別留意。
